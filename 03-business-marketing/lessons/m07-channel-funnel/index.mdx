## 퍼널 단계를 정의할 때

규칙: 단계마다 이벤트, 집계 단위, 기간 조건 세 칸을 모두 채운다. "관심 있는 방문"은 단계가 아니라 이름이다. "가격 페이지 조회"가 이벤트다.

가상 구독 서비스의 정의다.

| 단계 | 이벤트 | 집계 단위 | 기간 조건 |
|---|---|---|---|
| 도달 | 광고 노출(플랫폼 리포트) | 플랫폼이 세는 사람 수 | 집행 기간 |
| 클릭 | UTM이 붙은 랜딩 방문 | 사용자 | 집행 기간 |
| 가입 | 이메일 인증 완료 | 사용자 | 첫 방문 후 7일 이내 |
| 활성화 | 첫 핵심 행동(첫 프로젝트 생성) | 사용자 | 가입 후 7일 이내 |
| 결제 | 첫 결제 완료(환불 전) | 사용자 | 가입 후 30일 이내 |
| 재구매 | 두 번째 결제 완료 | 사용자 | 첫 결제 후 90일 이내 |

- 집계 단위는 한 퍼널에서 하나로 통일한다. 이벤트 횟수를 세면 한 사람이 여러 번 들어간다. 사용자 중복 제거는 d07에서 다룬다.
- 도달은 사람 수이고 클릭은 횟수라서 단위가 다르다. 사용자 퍼널은 사이트 첫 방문에서 시작하고, 도달에서 클릭은 광고 지표로 따로 본다.
- 분모는 직전 단계에 도달한 사람, 분자는 그중 기간 조건 안에 다음 단계를 한 사람이다.
- 기간 조건은 단계마다 적는다. 없으면 오래전 가입자의 결제가 이번 분자에 섞인다.
- 도구가 무엇이든 선택지를 명시한다. 예를 들어 GA4 퍼널 탐색은 단계를 이벤트나 차원 값으로 정의하고, 첫 단계 진입자만 세는 닫힌 퍼널과 어느 단계든 진입을 허용하는 열린 퍼널을 고르게 한다. 단계 사이에 다른 행동을 허용할지, 시간 제한을 둘지도 고른다.<Ref n={1} /> SQL 구현은 d07이다.

## 단계 사이의 순서와 기간을 정할 때

규칙: 첫 단계에 들어온 사람을 따라가며 센다(코호트). 같은 기간의 결제 수를 같은 기간의 가입 수로 나누지 않는다.

| 조건 | 규칙 | 어기면 |
|---|---|---|
| 순서 | 다음 단계 이벤트가 이전 단계 이후에 있어야 센다 | 가입 전에 결제한 기존 고객이 섞인다 |
| 진입 | 첫 단계 진입자만 센다(닫힌 퍼널) | 다른 경로 유입이 중간 단계에 들어와 전환율이 부풀거나 100%를 넘는다 |
| 사이 행동 | 사이에 다른 행동을 허용한다. 직접 연속 조건은 한 화면 안의 단계에만 쓴다 | 중간에 한 번 눌렀다고 이탈로 센다 |
| 기간 창 | 단계마다 이전 단계 시각 기준 상한을 둔다 | 상한이 없으면 오래된 사람이 섞이고, 너무 짧으면 늦은 전환이 빠진다 |
| 창 길이 | 자기 데이터에서 이전 단계 이후 걸린 일수를 모아 대부분(예: 90%)이 들어오는 일수로 정한다. 90%는 관행이다 | 감으로 정하면 단계마다 기준이 다르다 |
| 성숙 | 창이 아직 안 닫힌 코호트는 판정에서 뺀다 | 최근 코호트의 전환율이 낮게 나온다 |
| 반복 | 같은 사람이 같은 단계를 여러 번 하면 첫 발생만 센다 | 한 사람이 여러 번 센다 |

## 채널을 평가할 때

규칙: 채널은 이름이 아니라 여섯 가지 기준으로 본다. 기준마다 1점에서 5점을 주고, 점수는 내 상품과 내 타깃 기준으로 다시 매긴다.

| 기준 | 묻는 것 | 낮게 줄 때 |
|---|---|---|
| 고객 의도 강도 | 이 접점의 사람이 지금 해결책을 찾고 있는가 | 다른 것을 보다가 우연히 마주친다 |
| 도달 규모 | 내 타깃이 이 채널에서 몇 명까지 닿을 수 있는가 | 상한이 목표 전환에 못 미친다 |
| 비용 구조 | 노출당, 클릭당, 정액, 성과 중 무엇이고 내 허용 CAC와 맞는가 | 결과가 0이어도 나가는 선지급이 크다 |
| 효과 시간 | 집행에서 첫 전환까지 얼마나 걸리는가 | 판정까지 구매 주기와 전환 창 이상 걸린다 |
| 측정 가능성 | 채널에서 전환까지 사용자 단위로 연결되는가 | 링크·코드·UTM으로 묶을 방법이 없다 |
| 통제 가능성 | 예산·타깃·시점·메시지를 내가 조절하는가 | 매체나 알고리즘, 제3자가 정한다 |

비용 구조는 플랫폼의 입찰·과금 모델에서 갈린다. 예를 들어 Google Ads는 클릭당(CPC), 1,000회 노출당(CPM), 행동당(CPA) 모델을 구분한다.<Ref n={2} /> 아래 표는 구조의 상대 비교다. 수치가 아니고, 상품·시장·설정에 따라 달라진다.

| 유형 | 의도·도달 | 비용 구조 | 효과 시간 | 측정·통제 |
|---|---|---|---|---|
| 검색 광고 | 의도 강함. 도달은 검색량이 상한 | 클릭당이 일반적 | 바로 시작, 조정에 빠르게 반응 | 측정 쉬움, 통제 높음 |
| 소셜 유료 | 의도 약함. 도달은 예산으로 크게 조절 | 노출당·클릭당·성과 중 선택 | 바로 시작 | 플랫폼 안 측정은 쉬움(귀속은 m12), 통제 중간 |
| 오가닉 소셜 | 의도 약함. 도달은 팔로워와 알고리즘 | 인건비·제작비(정액) | 느리고 누적 | 측정 약함, 통제 낮음 |
| 콘텐츠·검색 최적화 | 의도 중간에서 강함. 쌓일수록 도달 증가 | 제작비(정액), 클릭은 무료 | 느림(m09) | 측정 중간, 통제 낮음 |
| 이메일 | 이미 접점이 있는 사람. 도달은 보유 목록이 상한 | 도구·제작비(정액) | 발송 즉시 | 측정 쉬움, 통제 높음(동의는 m13) |
| 제휴·추천 | 의도 중간. 도달은 파트너 규모 | 성과 수수료 또는 정액 | 계약 후 시작 | 링크·코드가 있어야 측정, 통제 낮음 |
| 인플루언서 | 의도 약함에서 중간. 도달은 계정 규모 | 정액 계약, 성과 혼합 가능 | 게시 시점에 몰림 | 링크·코드 없으면 측정 약함, 통제 낮음 |
| 언론 | 의도 약함. 신뢰 효과. 도달은 매체 규모 | 보도는 가격을 못 정함 | 시점 불확실 | 측정 약함, 통제 매우 낮음 |
| 오프라인 | 장소와 상황에 따라 다름. 도달은 지역 한정 | 임대·제작·인쇄(선지급 정액) | 게재 기간 고정 | 전용 QR·코드 없으면 측정 약함, 통제는 확정 후 낮음 |

- 의도가 약한 채널은 클릭이 싸도 가입 전환이 낮을 수 있다. 비교는 클릭당 비용이 아니라 최종 단계 1건당 비용으로 한다.
- 측정이 약한 채널은 효과가 없는 것이 아니라 못 보는 것이다. 점수를 낮게 주되 전용 링크나 코드를 먼저 붙인다.

## 채널의 테스트 예산을 정할 때

규칙: 예산은 "얼마 쓸까"가 아니라 "판단에 전환이 몇 건 필요한가"에서 거꾸로 계산한다.

| 용어(이 글의 정의) | 식 |
|---|---|
| 목표 전환 수 K | 판단할 단계의 전환 건수. 직접 정한다 |
| CVR | 해당 단계 전환 수 ÷ 클릭 수 |
| CPC | 광고비 ÷ 클릭 수 |
| 최소 테스트 예산 | `K ÷ CVR × CPC` |
| 허용 CAC | m06에서 정한 값 |

```python
K, cvr, cpc = 30, 0.02, 1000
clicks = K / cvr
print(clicks, clicks * cpc)
```

결과는 1,500클릭, 1,500,000원이다. CVR과 CPC는 모두 가정이라 한 값이 아니라 범위로 계산한다(K=30, 단위 만원).

| CPC \ CVR | 1% | 2% | 4% |
|---|---|---|---|
| CPC 500원 | 150 | 75 | 37.5 |
| CPC 1,000원 | 300 | 150 | 75 |
| CPC 1,500원 | 450 | 225 | 112.5 |

<Figure caption="예상 전환율이 절반이면 필요 예산은 2배다. 1%에서 4%의 범위로 계산해 75만원에서 300만원을 본다.">
  <BudgetCurve />
</Figure>

- 가장 나쁜 칸(450만원)을 감당할 수 없으면 그 채널은 이번에 테스트하지 않는다. 쪼개서 조금씩 쓰면 판정이 안 되고 돈만 쓴다.
- CPC는 소액으로 먼저 집행해 실측하고 식을 다시 계산한다. 일 예산이 10만원이면 150만원은 15일이다. 전환 창이 길면 그만큼 더한다.
- 전환 수가 판단의 정밀도를 정한다. 전환 K건으로 잰 전환율의 95% 상대 오차는 근사로 `1.96 ÷ √K`이다(푸아송 근사).

| K | 상대 오차 | 측정값을 100으로 볼 때 실제 범위 |
|---|---|---|
| 10 | 62% | 38에서 162 |
| 30 | 36% | 64에서 136 |
| 50 | 28% | 72에서 128 |
| 100 | 20% | 80에서 120 |

- K는 "허용 CAC의 몇 배부터 결정이 바뀌는가"로 고른다. 0.6배 이하나 1.4배 이상일 때만 결정이 갈린다면 K=30으로 충분하다.
- 상위 단계 전환으로 대신 테스트하면 예산이 준다. 가입 CVR 10%(가정)이면 K=30에 300클릭, 30만원이다. 단 가입에서 결제 연결은 가정이라 결제 CAC를 확정하지 못하고 채널끼리 가입 단가만 비교한다.
- 클릭이 없는 채널(이메일, 오프라인)은 클릭 대신 접촉 수로 `K ÷ 접촉당 전환율`을 계산한다. 비용은 정액이라 총액과 K로 건당 비용을 본다.

## 채널을 너무 일찍 접거나 너무 오래 끌 때

규칙: 판정은 사전에 적은 세 조건이 모두 찰 때만 한다. 하나라도 안 찼으면 "미판정"이고 접지도 키우지도 않는다.

| 조건 | 확인 |
|---|---|
| 표본 | 목표 전환 수 K 또는 계획한 클릭 수에 도달했는가 |
| 시간 | 전환 창과 효과 지연이 지났는가 |
| 예산 | 계획 예산을 썼거나 종료일이 되었는가 |

  <WilsonRanges />
</Figure>

일찍 접어도 되는 예외가 하나 있다. 전환이 0건일 때다. 손익분기 CVR은 `CPC ÷ 허용 CAC`이다(1,000 ÷ 50,000 = 2%, 가정). 실제 CVR이 이 값 이상이었다면 n클릭에서 0건이 나올 확률은 `(1-CVR)^n`이다.

| 클릭 수 n | 0건일 확률(CVR 2%) | 판정 |
|---|---|---|
| 100 | 13.3% | 미판정 |
| 150 | 4.8% | 손익분기 이상일 가능성이 낮다 |
| 300 | 0.2% | 접는다 |

간편식은 `n ≈ 3 ÷ 손익분기 CVR`이다(3 ÷ 0.02 = 150).<Ref n={3} /> 추적이 정상일 때만 쓴다. 0건은 태그 누락일 수도 있어 먼저 점검한다.

| 실수 | 판정 규칙 |
|---|---|
| 지연 전환을 못 기다리고 접는다 | 전환의 60%가 7일 안에 들어온다고 가정하면 첫 7일 결제 3건은 최종 약 5건이다. 7일 시점 CPA는 최종의 1.7배로 과대하다. 지연 비율은 내 데이터로 구한다 |
| 소표본의 우연으로 접거나 키운다 | 위 구간이 판정 가능 폭보다 넓으면 미판정 |
| 자동 입찰이 안정되기 전에 판단한다 | 플랫폼별 최소 전환 수와 학습 기간은 확인 필요(공식 문서 미확인) |
| 기준을 못 맞춘 채널을 증액해서 살린다 | 증액은 기준을 넘긴 채널에만 한다 |
| 종료일 없이 연장한다 | 종료일과 기준 CAC를 시작 전에 적고, 연장은 무엇을 바꿀지 가설이 있을 때만 한다 |
| 느린 채널을 클릭 예산으로 판정한다 | 선행 지표와 기간 상한을 시작 전에 정하고 그 기준으로 판정한다 |

## 채널 믹스를 정할 때

규칙: 동시에 돌릴 채널 수는 `총 테스트 예산 ÷ 채널당 최소 예산`을 내림한 값이다. 3,000,000 ÷ 1,500,000 = 2개다. 3개를 돌리면 어느 것도 판정하지 못한다.

- 점수 상위 채널부터 채우고 나머지 예산은 0으로 둔다. 고르게 나누지 않는다.
- 증액은 사전 기준(허용 CAC, 회수 기간)을 넘긴 채널에만 한다. 규모가 커지면 단가나 전환율이 달라질 수 있어 증액 뒤에도 같은 판정 규칙을 다시 적용한다.
- 70/20/10 같은 고정 비율은 관행일 뿐 근거 있는 값이 아니다. 비율 대신 검증된 채널의 성과와 테스트 채널의 최소 예산 단위, 잃어도 되는 금액으로 정한다.
- 한 채널이 신규 고객의 대부분이면 정책이나 단가가 바뀔 때 사업이 흔들린다. 상한은 감당할 손실로 정한다.
- 채널별 보고 전환을 합친 값이 실제 전환보다 클 수 있다. 같은 전환을 여러 채널이 자기 성과로 센다. 증분 효과는 m12에서 확인한다.

## 퍼널에서 막힌 곳을 찾을 때

규칙: ① 측정부터 점검한다(태그, 단계 정의, 미성숙 코호트). ② 단계 전환율을 목표나 이전 기간, 채널·기기별과 비교한다. ③ 달성률이 가장 낮은 단계부터 본다.

가상 퍼널은 200,000 → 4,000 → 600 → 150 → 30 → 9명이다. 목표는 이전 기간 평균이나 허용 CAC에서 역산한 값이다(가정).

<Figure caption="활성화 단계의 달성률이 62.5%로 가장 낮다. 낮은 절대값이 아니라 목표 대비로 병목을 고른다.">
  <FunnelBars />
</Figure>

- 최종 결제는 단계 전환율의 곱이다. 어느 단계든 상대 +10%이면 결제도 +10%(30건에서 33건)이다.
- 그래서 어디를 고칠지는 "목표 대비 갭"과 "고치기 쉬움"으로 정한다. 활성화를 목표 40%로 올리면 결제는 48건(+60%), 클릭률을 2.5%로 올리면 +25%이다.
- 앞 단계를 키우면 뒷 단계 품질이 바뀔 수 있다. 의도가 약한 클릭이 늘면 가입 전환이 떨어진다. 고친 뒤 전체를 다시 본다.
- 같은 퍼널을 채널별로 나눠 본다. 중간 단계가 채널마다 다르면 문제는 화면이 아니라 유입 의도다.

| 낮은 단계 | 먼저 확인 | 흔한 원인 | 고칠 곳 |
|---|---|---|---|
| 도달 → 클릭 | 소재·타깃별 클릭률 | 약속이 눈에 안 띔, 타깃 불일치 | 소재·타깃(m08) |
| 클릭 → 가입 | 클릭 수 대비 랜딩 도착, 폼 단계별 이탈, 속도 | 광고와 랜딩 불일치, 폼 항목 과다 | 랜딩(m11) |
| 가입 → 활성화 | 첫 가치까지의 단계 수 | 첫 행동이 멀다, 선택지 과다 | 온보딩(u04) |
| 활성화 → 결제 | 가격 노출 시점, 결제 오류 | 가치 확신 부족, 가격 충격 | 가격(m05), 결제 화면 |
| 결제 → 재구매 | 구매 주기 대비 창 길이 | 창이 짧음, 재접촉 없음 | 이메일·CRM(m10) |

## 흔한 실수

| 나쁜 예 | 고친 예 | 이유 |
|---|---|---|
| 단계를 "관심", "고려"로 부른다 | 이벤트·단위·기간으로 적는다 | 이름만으로는 집계가 안 된다 |
| 이번 주 결제 ÷ 이번 주 가입 | 가입 코호트가 창 안에서 결제한 비율 | 가입이 몰리면 비율이 요동친다 |
| 채널 5개에 예산을 나눈다 | 총예산 ÷ 최소 예산만큼만 채널을 연다 | 어느 채널도 표본이 안 찬다 |
| 3일 만에 결제 0건이라 접는다 | n ≥ 3 ÷ 손익분기 CVR와 추적 정상일 때만 접는다 | 소표본과 지연 전환 |
| 전환율이 낮은 단계를 무조건 고친다 | 목표 대비 달성률이 낮은 단계를 본다 | 단계마다 정상 수준이 다르다 |

## 증상으로 찾기

| 증상 | 원인 | 처방 |
|---|---|---|
| 퍼널 전환율이 주마다 크게 흔들린다 | 같은 주 분자와 분모, 미성숙 코호트 | 코호트 기준과 창이 닫힌 코호트만 사용 |
| 어떤 단계 전환율이 100%를 넘는다 | 열린 퍼널이거나 단위가 이벤트 횟수 | 닫힌 퍼널, 사용자 단위로 통일 |
| 광고 클릭 수와 랜딩 방문 수가 다르다 | 추적 누락, 로딩 중 이탈, 단위 차이 | 두 값을 따로 쓰고 차이가 큰 구간을 점검 |
| 전환이 0건이다 | 채널 문제 또는 추적 오류 | 테스트 전환 이벤트로 추적 확인 후 위 접는 규칙 |
| 채널 보고 합이 실제 전환보다 크다 | 중복 귀속 | 실제 주문 기준으로 합계를 보고 m12로 확인 |
| 규모를 키웠더니 CAC가 오른다 | 단가나 전환율 변화 | 증액 구간별로 판정 규칙을 다시 적용 |
| 가입은 느는데 결제가 안 는다 | 의도 약한 유입, 활성화 병목 | 채널별 퍼널과 활성화 달성률 확인 |

## 점검 체크리스트

- 각 단계에 이벤트 1개, 집계 단위, 기간 조건이 적혀 있는가.
- 퍼널이 닫힌 퍼널이고 사용자 단위이며 코호트 기준인가.
- 창이 안 닫힌 최근 코호트를 판정에서 뺐는가.
- 채널을 여섯 기준으로 점수화했고 가중치 두 벌로 순서를 확인했는가.
- 채널당 최소 예산을 K, CVR 범위, CPC 범위로 계산했고 가정을 적었는가.
- 동시에 여는 채널 수가 총예산 ÷ 최소 예산 이하인가.
- 접는 기준, 종료일, 기준 CAC가 집행 전에 적혀 있는가.
- 병목 판정을 목표 대비 달성률로 했고 측정 오류부터 배제했는가.

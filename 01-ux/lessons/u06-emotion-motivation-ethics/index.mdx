## 흐름의 끝을 설계할 때

사람은 경험을 가장 강했던 순간과 마지막 순간 위주로 평가하는 경향이 있다. 그래서 흐름을 점검할 때 이 지점부터 본다.

| 지점 | 해라 | 하지 마라 |
|---|---|---|
| 오류, 실패 화면 | 원인, 해결 방법, 되돌아갈 길을 보여준다 | 코드만 띄우거나 처음부터 다시 하게 한다 |
| 마지막 단계(결제, 제출) | 입력값을 보존하고 오류를 줄인다 | 마지막에 추가 비용이나 필수 입력을 꺼낸다 |
| 완료 화면 | 완료를 분명히 알리고 다음 행동 하나를 안내한다 | 빈 화면이나 광고로 끝낸다 |
| 해지, 탈퇴 마무리 | 정중한 확인 한 번 뒤 바로 완료한다 | 해지를 막는 설득을 반복한다 |

<Figure caption="평범한 구간은 막힘만 없애고, 오류 복구와 마지막 단계와 완료 화면에 공을 먼저 들인다. 단계 이름은 예시다.">
  <PeakEndPoints />
</Figure>

<Callout kind="warn">
근거가 된 연구는 통증, 불쾌 경험의 사후 평가다. 웹, 앱 화면 흐름에서의 효과 크기는 직접 재지 않았다. 메타분석에서는 전체 평균도 평가를 비슷하게 예측했다.<Ref n={1} /> 어디를 먼저 점검할지 정하는 가설로 쓰고, 끝 연출로 중간 문제를 덮지 않는다.
</Callout>

## 진행률과 목표를 보여줄 때

목표에 가까워질수록 사람은 빨라지는 경향이 있다. 진행률 바, 단계 표시, 적립 카드가 이 효과를 쓰는 설계다.

| 항목 | 기준 | 비고 |
|---|---|---|
| 남은 단계 | 실제 개수를 정확히 보여준다 | 중간에 단계를 추가하지 않는다 |
| 시작 지점 미리 채우기 | 혜택이라고 밝히고, 조건을 선택 전에 보여준다 | 12칸 카드에 2칸을 미리 찍어도 필요한 구매는 10번으로 같았다. 완료까지 평균 12.7일 대 15.6일로 약 20% 빨랐다<Ref n={2} /> |
| 목표 달성 직후 | 다음 목표를 바로 이어준다 | 첫 보상 뒤에는 속도가 일시적으로 느려졌다<Ref n={2} /> |

<Figure caption="같은 구매 10번이라도 시작 지점이 채워진 카드가 더 빨리 완료됐다. 숫자는 현장 실험의 보고값이고 카드 모양은 단순화했다.">
  <GoalGradientCards />
</Figure>

| 구분 | 돕는 설계 | 속이는 설계 | 판별 질문 |
|---|---|---|---|
| 진행률 | 실제 남은 단계를 보여준다 | 단계를 숨겼다가 중간에 추가한다. 가짜로 채운 진행률 | 이 숫자가 사실인가 |
| 사전 적립 | 혜택임을 밝히고 조건을 알린다 | 숨은 조건으로 묶어 가입을 유도한다 | 조건이 선택 전에 보이는가 |

<Callout kind="warn">
표본은 한 대학 카페의 고객이다. 다른 서비스와 보상에 그대로 일반화하지 않는다. 진행률 바를 넣으면 이탈이 준다는 보장도 없다.
</Callout>

## 몰입을 지키고 싶을 때

과제의 난이도를 사용자 능력에 맞춘다. 몰입 조건은 도전과 능력의 균형, 분명한 가까운 목표, 즉각적인 피드백이다.<Ref n={3} />

| 증상 | 원인 | 처방 |
|---|---|---|
| 시작하다 불안해하며 포기한다 | 도전이 능력보다 크다 | 단계별 안내, 쉬운 시작, 되돌리기 수단 |
| 반복 작업에서 지루해 이탈한다 | 능력이 도전보다 크다 | 숙련자용 단축 경로, 점진적 난이도 |
| 지금 뭘 해야 할지 모른다 | 가까운 목표가 불분명하다 | 한 화면에 과제 하나, 다음 행동 하나 표시 |
| 잘되고 있는지 모른다 | 피드백이 늦다 | 입력 직후 결과를 보여준다 |

- 하지 마라: 사용자가 과제 중일 때 불필요한 팝업, 알림, 모달로 끊지 않는다(해석).
- 하지 마라: 체류 시간으로 몰입을 판단하지 않는다. 몰입은 주관적 상태라 자기보고로만 잰다.
- 하지 마라: 사용 시간을 늘리는 것 자체를 목표로 삼지 않는다. 중독적 설계와 가까워진다.

## 행동이 일어나지 않을 때

행동은 동기, 능력, 촉발(지금 하라는 신호)이 같은 순간에 모일 때 일어난다. 안 일어났다면 셋 중 하나가 빠진 것이다.<Ref n={4} /> 처방이 쉬운 촉발과 능력부터 본다.

<Figure caption="촉발, 능력, 동기 순으로 묻고 아니오가 나오는 곳에서 처방한다.">
  <FoggFlow />
</Figure>

| 증상 | 부족한 요소 | 처방 |
|---|---|---|
| 하고 싶고 할 수 있는데 안 한다 | 촉발 | 알맞은 때와 장소에서 신호를 준다 |
| 알림은 열지만 행동하지 않는다 | 능력 | 행동을 더 작게 줄이고 단계를 덜어낸다 |
| 시작은 쉬운데 반응이 없다 | 동기 | 사용자가 얻는 가치를 분명히 한다 |

능력은 시간, 돈, 신체 노력, 정신 노력, 일상 루틴 중 가장 부족한 자원을 줄여서 올린다.<Ref n={4} /> 동기에 기대는 것보다 행동을 작게 줄이는 쪽이 설계로 다루기 쉽다.

<Callout kind="warn">
발견적 틀이지 예측 공식이 아니다. 촉발을 늘리면 행동이 늘 것이라는 생각이 알림 남발로 이어지면 반복 간섭이라는 다크패턴이 된다.
</Callout>

## 돕는 설계인지 판별할 때

같은 원리(진행률, 알림, 기본값)라도 사용자가 알고 선택하느냐로 갈린다. 쓰기 전에 네 질문을 던지고, 하나라도 아니오면 설계를 바꾼다. 법적 요건의 전부는 아니다.

<Figure caption="네 질문 중 하나라도 아니오이면 다크패턴을 의심하고 설계를 바꾼다.">
  <EthicsGate />
</Figure>

| 기준 | 돕는 설계 | 속이는 설계의 신호 |
|---|---|---|
| 이해한 상태의 선택 | 가격, 갱신, 데이터 사용을 선택 전에 보여준다 | 마지막 단계에서 추가 비용이 나온다 |
| 거절, 해지의 대칭 | 해지가 가입과 같은 방법이고 단계 수도 비슷하다 | 해지는 전화나 여러 단계 뒤에만 가능하다 |
| 기본값, 시각 위계 | 사용자 이익에 맞는 기본값. 거절 버튼도 같은 크기 | 부가 상품이 미리 체크돼 있다. 거절 버튼이 흐리다 |
| 진실성 | 마감, 재고, 후기가 사실이다 | 매번 리셋되는 카운트다운, 가짜 재고 |
| 사용자 목표와의 일치 | 사용자가 정한 목표를 돕는다 | 사용 시간을 늘리는 것 자체가 목적이다 |
| 거절의 존중 | 거절하면 일정 기간 다시 묻지 않는다 | 거절해도 팝업이 계속 뜬다 |
| 취약한 사용자 | 아동과 취약층에게 더 보수적이다 | 부담이 큰 결정을 압박한다 |

## 다크패턴 유형과 고치는 법

아래 유형은 deceptive.design의 목록(확인 시점 2026년 10월) 중 실무에서 자주 나오는 것이다.<Ref n={5} /> 한국법 열 대응은 필자의 정리이며 법 문언과 완전히 일치하지 않는다.

| 유형 | 이렇게 하면 다크패턴 | 이렇게 고쳐라 | 한국법 |
|---|---|---|---|
| 숨은 비용 | 낮은 가격으로 유인하고 결제 단계에서 추가 요금을 붙인다 | 첫 가격 표시에 필수 총금액을 보여준다 | 제21조의2 제1항 제1호 |
| 사전선택 | 부가 상품, 동의가 미리 체크돼 있다 | 체크를 비워 두고 사용자가 직접 고르게 한다 | 제2호 |
| 시각적 간섭 | 거절 버튼을 흐리게 하거나 숨긴다 | 선택지의 크기, 색, 위치를 대등하게 한다 | 제3호(부분 대응) |
| 해지 어려움 | 가입은 클릭 몇 번, 해지는 전화나 여러 단계 | 가입과 같은 방법, 같거나 짧은 단계로 해지한다 | 제4호 |
| 반복 간섭 | 거절한 요청을 팝업으로 계속 묻는다 | 거절하면 일정 기간 묻지 않는다 | 제5호 |
| 숨은 구독 | 고지와 동의 없이 정기결제로 전환하거나 증액한다 | 변경 전에 동의를 받고 해지 방법을 알린다 | 제13조 제6항 |
| 가짜 긴박감, 희소성, 사회적 증거 | 리셋되는 타이머, 거짓 재고, 거짓 후기 | 실제 마감일, 실제 재고, 실제 후기만 쓴다 | 열거 유형 아님. 확인 필요 |
| 컨펌셰이밍 | 거절 선택지에 죄책감 문구를 붙인다 | 중립적인 아니오로 쓴다 | 해당 유형 없음. 확인 필요 |
| 중독적 설계 | 심리적 취약점으로 과도한 사용을 유도한다 | 사용자가 정한 목표를 돕는 기능만 넣는다 | 해당 유형 없음. 확인 필요 |

<Callout kind="warn">
약한 다크패턴도 효과가 있다. 미국 성인 실험에서 의심스러운 서비스 가입 확률이 통제 집단의 두 배 넘게 올랐고, 학력이 낮은 참가자가 더 취약했다.<Ref n={6} /> 전환율이 올랐다는 것은 정당성의 증거가 아니다. 합법이라고 윤리적인 것도 아니다. 한국법은 일부 유형만 규율한다.
</Callout>

## 알림, 스트릭, 진행 표시를 넣을 때

| 대상 | 해라 | 하지 마라 | 점검 질문 |
|---|---|---|---|
| 알림 | 사용자가 시간과 주제를 정하게 하고 쉽게 끄게 한다 | 거절 후에도 반복한다. 끄는 설정을 숨긴다 | 끄는 것이 켜는 것만큼 쉬운가 |
| 스트릭(연속 기록) | 사용자가 정한 목표를 돕고 쉬어 가는 방법을 준다 | 끊기면 죄책감 문구를 띄우고 복구를 결제로만 푼다 | 쉬어도 불이익이 과도하지 않은가 |
| 진행 표시 | 실제 남은 단계를 보여준다 | 가짜로 채우거나 중간에 단계를 추가한다 | 이 숫자가 사실인가 |
| 한정 혜택 | 실제 마감일을 표시한다 | 새로 고침하면 다시 시작하는 타이머 | 마감이 실제로 있는가 |

| 항목 | 내용 |
|---|---|
| 개정 | 법률 제20302호, 2024년 2월 13일 공포<Ref n={7} /> |
| 시행 | 2025년 2월 14일(공포 후 1년). 제21조의2 제2항(지침)과 제21조의3(자율규약)은 공포일부터 시행<Ref n={7} /> |
| 대상 | 전자상거래 사업자, 통신판매업자가 운영하는 온라인 인터페이스(웹사이트, 모바일 앱) |
| 제재 | 시정조치 대상. 제45조 제4항에 따라 현행 조문 기준 1천만 원 이하 과태료<Ref n={7} /> |
| 해석 지침 | 공정위가 지침 개정을 2025년 10월 24일부터 시행(보도자료 요약으로 확인, 원문 확인 필요)<Ref n={8} /> |

| 유형(조문) | 금지되는 것 | 통과 기준 |
|---|---|---|
| 숨은 갱신(제13조 제6항) | 정기결제 대금을 올리거나 무료에서 유료로 전환하기 전에, 시행령이 정한 기간 내 동의를 받고 해지 조건과 방법을 고지하지 않는 것 | 증액, 유료 전환 전에 동의를 받고 해지 방법을 알렸다 |
| 순차공개 가격책정(제21조의2 제1항 제1호) | 첫 화면에 필수 총금액의 일부만 표시해 유인하는 것. 정당한 사유가 있고 알린 경우는 예외 | 첫 가격 표시에 필수 총금액이 보인다 |
| 특정옵션 사전선택(제2호) | 다른 상품이나 가입의 청약 의사를 묻는 항목을, 소비자가 선택하기 전에 이미 청약한 것처럼 표시하는 것 | 부가 상품과 동의가 미리 체크되지 않는다 |
| 잘못된 계층구조(제3호) | 선택항목의 크기, 모양, 색을 현저히 다르게 해 특정 항목만 선택할 수 있거나 반드시 선택해야 하는 것처럼 오인시킬 우려가 있는 것 | 거절 선택지도 같은 수준으로 읽히고 눌린다 |
| 취소, 탈퇴 방해(제4호) | 정당한 사유 없이 취소, 탈퇴, 해지 절차를 가입보다 복잡하게 하거나 가입과 다른 방법으로만 하게 제한하는 것 | 가입과 같은 방법이고 단계가 더 길지 않다 |
| 반복간섭(제5호) | 이미 한 선택의 변경을 팝업 등으로 반복 요구하는 것. 일정 기간 요구받지 않도록 선택하게 한 경우는 예외 | 거절 후 일정 기간 다시 묻지 않는다 |

<Callout kind="warn">
이 글은 법률 자문이 아니다. 열거된 6개 유형 밖의 가짜 긴박감, 가짜 후기, 컨펌셰이밍은 제21조의2에 직접 없다. 적용 여부는 확인 필요. 2026년 1월 20일 개정분(일부 2026년 7월 21일 시행)이 있으니 현행 조문과 공정위 지침을 직접 확인한다.<Ref n={7} />
</Callout>

## 해외 서비스를 낼 때

- EU: Digital Services Act 제25조는 온라인 플랫폼이 이용자를 속이거나 조종하는 인터페이스를 금지한다. 대표 관행은 한 선택지만 두드러지게 보이기, 이미 한 선택을 팝업으로 반복 요구하기, 해지를 가입보다 어렵게 하기다.<Ref n={9} />
- 미국: FTC는 2022년 9월 직원 보고서에서 사례를 4개 범주로 정리했다. 잘못된 믿음 유도, 중요 정보 숨김 또는 공개 지연, 무단 청구로 이어지는 설계, 개인정보 선택 은폐 또는 훼손이다. 새 법이 아니라 사례 정리다.<Ref n={10} />
- 미국 사례: 2025년 9월 25일 Amazon Prime 합의에서 FTC는 혼란스러운 가입 화면과 복잡한 해지를 문제 삼았다. 조건에 거절 버튼 명확화와 가입과 같은 방식의 쉬운 해지가 들어갔다. 위법 인정 여부는 확인 필요.<Ref n={11} />

## 흔한 실수

| 실수 | 왜 틀리나 | 대신 |
|---|---|---|
| 끝 화면만 다듬는다 | 전체 평균도 평가를 예측한다 | 중간 막힘을 먼저 고친다 |
| 진행률 바를 넣으면 이탈이 준다고 믿는다 | 보상이 있는 카페 카드 연구의 결과다 | 실제 남은 단계를 보여주고 직접 측정한다 |
| 동기만 올리려 한다 | 능력을 올리는 길이 더 다루기 쉽다 | 행동을 작게 줄인다 |
| 전환율이 올랐으니 괜찮다고 본다 | 다크패턴도 전환을 올린다 | 성공 지표가 사용자 이익과 충돌하는지 검토한다 |

## 점검 체크리스트

- 오류 화면에 원인, 해결 방법, 되돌아갈 길이 있다.
- 완료 화면이 완료를 알리고 다음 행동 하나를 안내한다.
- 진행률은 실제 남은 단계를 보여주고, 사전 적립은 조건이 선택 전에 보인다.
- 과제 중에 불필요한 알림과 팝업이 뜨지 않는다.
- 마감, 재고, 후기 표시가 사실이다.
- 알림은 사용자가 시간과 주제를 정하고 끌 수 있다.
- 해지가 가입보다 길지 않고, 거절하면 일정 기간 다시 묻지 않는다.
- 성공 지표가 사용자 이익과 충돌하지 않는다.

<Overview>

- 해라: 사용자가 막혔다는 보고를 받으면 고치기 전에 층(표면, 골격, 구조, 범위, 전략)부터 정해라. 층을 잘못 짚으면 엉뚱한 곳을 고친다.
- 해라: 화면 층(표면, 골격)은 기준값으로, 구조 이하는 처음 쓰는 사람의 행동 관찰로 확인해라.
- 해라: 실패했을 때의 동작(뒤로가기, 오류, 이탈)을 화면 목록과 따로 설계해라.
- 하지 마라: 시안에 대한 호감 반응을 사용성 근거로 쓰지 마라.
- 기준값: 글자 대비 4.5:1(큰 글자 3:1), UI 요소 대비 3:1, 터치 영역 최소 24px에 권장 44pt 또는 48dp.

</Overview>

## 막혔다는 보고를 받았을 때

UX 문제는 5개 층 중 어디서 났는지 정한 뒤 고친다. 층은 위부터 표면, 골격, 구조, 범위, 전략이다. 아래층의 결정이 위층의 선택지를 정한다.<Ref n={1} />

| 증상 | 의심할 층 | 먼저 볼 것 |
|---|---|---|
| 글자가 안 읽힌다, 산만해 보인다 | 표면 | 글자 대비, 글자 크기, 스타일 일관성 |
| 눌러야 할 곳을 못 찾는다, 오조작이 난다 | 골격 | 버튼 배치와 간격, 터치 영역 크기 |
| 원하는 곳으로 가지 못하고 되돌아온다 | 구조 | 분류 이름, 메뉴 구조, 흐름의 단계 수 |
| 기능은 많은데 안 쓰이거나, 필요한 기능이 없다 | 범위 | 핵심 과업 대비 기능 목록 |
| 가입한 뒤 떠난다, 쓸 이유가 없다 | 전략 | 사용자가 얻고 싶은 것, 제품의 약속 |
| 예쁘다는 말은 듣는데 완수율이 낮다 | 아래층 전체 | 사용자가 실제로 쓰는 모습 관찰 |

증상으로 층이 안 정해지면 위에서 아래로 소거한다. 수치로 닫을 수 있는 층을 먼저 닫는다.

## 층별로 던질 확인 질문

<Figure caption="표면과 골격은 기준 수치로, 구조 이하는 사용자 관찰로 확인한다.">
  <PlanesStack />
</Figure>

| 층 | 확인 질문 |
|---|---|
| 표면 | 글자가 읽히는가. 화면마다 스타일이 같은가. 장애가 있어도 쓸 수 있는가 |
| 골격 | 눌러야 할 곳이 보이는가. 오조작 없이 누를 수 있는가 |
| 구조 | 목표까지 몇 단계인가. 처음 보는 사람이 분류 이름을 이해하는가. 찾는 것을 찾을 수 있는가. 실패했을 때 입력이 남는가 |
| 범위 | 핵심 과업에 필요한 기능이 다 있는가. 안 쓰는 기능이 핵심을 가리는가 |
| 전략 | 사용자가 얻는 것이 무엇인가. 믿을 만한가. 사업에도 가치가 있는가 |

## 화면 층을 점검할 때

표면과 골격에는 수치로 검증할 기준이 있다. 이 기준을 먼저 통과시킨다.

| 항목 | 기준 | 비고 |
|---|---|---|
| 본문 글자 대비 | 4.5:1 이상(AA) | 7:1 이상이면 AAA. WCAG 1.4.3, 1.4.6<Ref n={2} /> |
| 큰 글자 대비 | 3:1 이상 | 큰 글자는 18pt(약 24px) 이상 또는 굵은 14pt(약 18.7px) 이상 |
| 버튼, 아이콘 등 UI 요소 대비 | 인접한 색과 3:1 이상 | WCAG 1.4.11 |
| 터치 영역 최소 | 24×24 CSS px 이상 | 간격이 충분하면 예외. WCAG 2.5.8(AA) |
| 터치 영역 권장 | iOS 44×44pt, Android 48×48dp | Apple HIG, Material Design<Ref n={3} /> |
| 터치 영역 강화 | 44×44 CSS px | WCAG 2.5.5(AAA) |

<Figure caption="같은 회색 계열이라도 4.5:1을 넘느냐에 따라 통과와 미달이 갈린다. 비율은 WCAG 공식으로 계산한 값이다.">
  <Contrast />
</Figure>

<Figure caption="터치 영역은 24px가 하한이고, 실제 설계는 44pt 또는 48dp를 목표로 한다.">
  <TouchTargets />
</Figure>

| 나쁜 예 | 고친 예 | 이유 |
|---|---|---|
| 옅은 회색 글자 #999999를 흰 배경에 쓴다(2.85:1) | #767676 이상으로 어둡게 한다(4.54:1) | 4.5:1 미달이면 본문 기준을 통과하지 못한다 |
| 아이콘 24px 그대로를 터치 영역으로 쓴다 | 아이콘은 두고 패딩으로 44~48 영역을 만든다 | 아이콘 크기와 터치 영역은 따로 정한다 |
| 작은 버튼을 간격 없이 붙여 둔다 | 영역을 키우거나 간격을 둔다 | 간격이 충분해야 24px 미만이 예외가 된다 |

눌리는 것은 눌리게 보이게 하라. 밀어야 하는 문에 당기는 손잡이를 다는 식으로 신호와 동작이 어긋나면 틀린 것은 사용자가 아니라 설계다. 설명이 필요해진 시점에 이미 신호 설계는 실패했다.

<Callout kind="warn">
기준을 채웠다고 좋은 UX가 되는 것은 아니다. 대비와 크기가 완벽해도 흐름이 틀리면 사용자는 막힌다.
</Callout>

## 흐름이 길거나 끊길 때

버튼 모양과 색이 같아도 단계 수와 실패했을 때의 동작이 다르면 다른 UX다. 화면 캡처로는 구분되지 않는다.

<Figure caption="같은 UI에서 흐름만 다르다. 실패했을 때의 동작(삭제 대 자동 저장)을 설계 항목에 넣어야 한다. 가정한 예시이며 실제 서비스 화면이 아니다.">
  <FlowCompare />
</Figure>

| 나쁜 예 | 고친 예 | 이유 |
|---|---|---|
| 뒤로가기 한 번에 작성 내용이 삭제된다 | 입력 중 자동 임시저장, 나가도 이어서 쓴다 | 실패 동작은 화면 디자인 목록에 안 나와 빠뜨리기 쉽다 |
| 글쓰기 전에 카테고리를 고르게 한다(5단계) | 본문부터 쓰고 분류를 추천한다(4단계) | 사용자가 모르는 것을 먼저 묻지 않는다 |

## 사용성을 점검할 때

사용성은 학습, 효율, 기억, 오류, 만족 다섯 가지 질문으로 점검하고, 각 질문을 지표로 바꾼다.<Ref n={4} />

| 품질 | 확인 질문 | 지표 |
|---|---|---|
| 학습 | 처음 보는 사용자가 안내 없이 기본 과업을 끝내는가 | 첫 시도 완수율 |
| 효율 | 익숙해진 뒤 빠르게 끝내는가 | 소요 시간, 클릭·탭 수 |
| 기억 | 한동안 안 쓰다 돌아와도 바로 쓰는가 | 복귀 사용자의 완수율, 소요 시간 |
| 오류 | 실수가 얼마나 자주 나고 복구가 쉬운가 | 오류 횟수, 복구 성공 여부 |
| 만족 | 쓰는 것이 불쾌하지 않고 다시 쓰고 싶은가 | SUS 점수 |

| 지표 | 보는 것 | 읽는 법 |
|---|---|---|
| 과업 완수율 | 과업을 끝낸 사용자 비율 | 낮으면 막히는 지점을 찾는다 |
| 소요 시간 | 과업을 끝내는 데 걸린 시간 | 같은 과업의 전후와 비교한다 |
| 오류 수 | 과업 중 잘못 누르거나 되돌린 횟수 | 오류가 몰리는 화면을 본다 |
| SUS | 10문항 설문, 0에서 100점<Ref n={5} /> | 평균은 약 68점. 합격선이 아니다 |

<Callout kind="warn">
SUS 68점은 평균일 뿐이다. 다른 제품과 비교하거나 같은 제품의 전후를 비교할 때 쓴다. 평균 68점은 측정 전문 업체의 정리를 확인한 값이고, 연구 원문은 확인하지 않았다.
</Callout>

## 흔한 실수

| 하지 마라 | 이렇게 | 이유 |
|---|---|---|
| 시안에 대한 호감 반응을 사용성 근거로 쓴다 | 과업을 주고 완수율과 오류를 잰다 | 호감이 불편을 가려 문제가 덜 드러날 수 있다<Ref n={6} /> |
| 쉬우면 UX가 좋다고 끝낸다 | 쓸모, 신뢰, 접근성까지 확인한다 | 쉬워도 필요 없으면 쓰지 않는다 |
| 만든 사람의 눈으로 확인한다 | 처음 쓰는 사람의 행동을 관찰한다 | 만든 사람은 이미 구조를 안다 |
| 기능을 늘려서 해결한다 | 핵심 과업 기준으로 기능 목록을 줄인다 | 선택지가 늘수록 결정 비용이 커진다 |
| 사용자에게 무엇이 불편한지 묻는 것으로 끝낸다 | 말보다 행동을 관찰한다 | 사용자는 자기 행동을 정확히 설명하지 못할 때가 많다 |

## 점검 체크리스트

- 막힌 지점을 증상 표로 층에 배정했는가
- 본문 글자 대비가 4.5:1 이상, UI 요소 대비가 3:1 이상인가
- 터치 영역이 최소 24px를 넘고 주요 버튼은 44pt 또는 48dp 이상인가
- 뒤로가기, 새로고침, 오류 뒤에도 입력한 내용이 남는가
- 눌리는 것은 눌리게 보이는가
- 시안 호감이 아니라 과업 완수율과 오류 수로 판단했는가
- 처음 쓰는 사람의 행동을 한 번이라도 직접 봤는가

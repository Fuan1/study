## 실험을 설계할 때

규칙: 결과를 보기 전에 아래 표를 채워 고정한다. 나중에 지표나 기간을 바꾸면 판정이 무효가 된다.

| 항목 | 정하는 것 | 규칙 |
|---|---|---|
| 가설 | 무엇을 바꾸면 어떤 지표가 얼마나 움직이는가 | 방향과 최소 검출 효과(MDE)까지 쓴다 |
| 무작위 단위 | 사용자, 세션, 기기 중 하나 | 사용자가 기본. 경험이 이어지는 기능은 세션 단위로 나누지 않는다 |
| 주지표 | 판정에 쓰는 지표 1개 | 분석 단위는 무작위 단위와 같게 둔다 |
| 보조 지표 | 이유를 설명하는 지표 | 판정에 쓰지 않는다 |
| 가드레일 | 나빠지면 안 되는 지표(속도, 오류, 환불) | 허용 악화 폭을 미리 정한다 |

| 기간 | 표본 수와 요일 주기로 정한 일수 | 도중에 바꾸지 않는다 |

- 세션이나 기기 단위로 배정하면 같은 사람이 양쪽을 겪는다. 대상 조건은 배정 전에 정한다. 배정 후 행동으로 거르면 두 군이 달라진다.
- 가드레일은 "개선 증명"이 아니라 "악화 감시"다. 표본이 모자라 못 잡을 수 있으니 허용 폭과 함께 쓴다.

## 표본 수를 계산할 때

규칙: MDE, 검정력, 유의수준을 정하고 군당 표본 수를 계산한다. 관측한 효과로 거꾸로 정하지 않는다.

두 군이 같은 크기이고 양측 검정일 때 군당 표본 수는 다음과 같다.<Ref n={1} />

- 평균 비교: `n = 2σ²(z(1-α/2) + z(1-β))² / δ²`
- 비율 비교: σ² 자리에 `p(1-p)`를 쓴다. p는 두 군 비율의 평균이다.
- 어림: α=0.05(양측), 검정력 1-β=0.8이면 `2(1.96+0.84)² ≈ 15.7`이라 `n ≈ 16σ²/δ²`이다. 군당 값이다.

| 가정 | 값 | 바꾸면 |
|---|---|---|
| 유의수준 α | 0.05, 양측 | 0.01이면 표본이 약 49% 늘어난다(14,752에서 21,951) |
| 검정력 | 80% | 90%이면 약 34% 늘어난다(14,752에서 19,749) |
| σ | 실험 직전 몇 주의 같은 지표 표준편차 | 지표 정의가 바뀌면 다시 계산 |
| 군 크기 | 같음 | 95 대 5이면 시간이 약 5배, 99 대 1이면 약 25배<Ref n={2} /> |

```python
from statistics import NormalDist
import math

z = NormalDist().inv_cdf

def n_prop(p1, p2, a=0.05, pw=0.8):
    pb = (p1 + p2) / 2
    d = p2 - p1
    k = z(1 - a / 2) + z(pw)
    v = 2 * pb * (1 - pb)
    return v * k**2 / d**2

print(math.ceil(n_prop(0.10, 0.11)))
```

| 입력(가정) | 정확한 식 | 어림 `16σ²/δ²` |
|---|---|---|
| 전환율 10%에서 11%(MDE 1%p) | 14,752 | 14,400 |
| 평균 비교, σ=30, 차이 1.5 | 6,280 | 6,400 |
| 전환율 10%에서 12%(상대 20%) | 3,843 | 3,601 |

어림은 MDE가 클수록 오차가 커진다. 계획서에는 정확한 식의 값을 쓴다. 기저 전환율이 낮으면 표본이 크게 는다(2%에서 2.2%는 80,683).

<Figure caption="MDE를 절반으로 줄이면 필요한 표본은 약 4배다. 기저 전환율 10%는 가정이다.">

</Figure>

- MDE는 "출시할 가치가 있는 최소 차이"다. 표본이 모자라면 MDE를 키워 맞추지 말고 기간을 늘리거나 접는다.
- 일수는 총 표본을 일일 유입으로 나눈다. 총 29,504명, 하루 5,000명이면 5.9일이다.

## 기간을 정할 때

규칙: 계산한 일수를 7의 배수로 올림한다. 이것은 업계 관행이며 근거는 요일 효과다.

주말 방문자는 평일과 다른 집단이라 일 단위로 끊으면 요일이 쏠린다. 원문은 최소 1주에서 2주를 돌리고 이후 주 단위로 늘리라고 권한다.<Ref n={2} />

일일 유입이 2,000명이면 14.8일이라 21일, 5,000명이면 5.9일이라 7일, 10,000명이면 3.0일이라 7일이다(총 29,504명 기준).

- 배정 시점이 다른 사용자는 관찰 시간이 다르다. 배정 후 7일처럼 같은 관찰 창을 모두에게 적용한다.
- 너무 긴 기간(원문 예는 125일 초과)은 쿠키 소실 등으로 오염될 수 있다.<Ref n={2} /> 일수가 너무 길면 MDE나 지표를 다시 정한다.

신규 효과(일단 눌러 본다)와 기존 사용자의 적응 지연은 반대 방향이고 둘 다 몇 주를 돌려야 하는 이유다.<Ref n={2} /> 확인 방법은 다음과 같다.

- 배정 후 경과일별로 효과를 그린다. 처음에 크다가 줄면 신규 효과를 의심한다.
- 신규 사용자 군에서만 주지표를 계산한다. 신규 효과와 적응 지연의 영향이 없다.<Ref n={2} />
- 7일 단위로 더 돌려 효과가 안정되는지 본다.

## 결과를 열기 전에 SRM을 확인할 때

규칙: 설계한 배정 비율과 실제 사용자 수 비율이 다르면(SRM) 결과 해석을 멈춘다. 대부분의 경우 결과가 무효가 된다.<Ref n={3} />

Microsoft에서는 실험의 약 6%에서 SRM이 나타났다.<Ref n={3} /> 먼저 군별 사용자 수를 센다(가상 테이블 `assignments`, 사용자당 1행).

```sql
SELECT variant,
       COUNT(*) AS users
FROM assignments
GROUP BY variant;
```

| variant | users |
|---|---|
| A | 15063 |
| B | 14937 |

설계가 50 대 50이면 기대값은 합계의 절반(14,950)이다. 카이제곱 통계량은 `합계((관측 - 기대)² / 기대)`이고 여기서는 0.5292이다. p값은 python에서 계산한다. 군이 2개면 자유도 1이고 `math.erfc(math.sqrt(chi2 / 2))`이므로 p=0.467로 정상이다.

| 관측(A 대 B) | 비율 | chi2 | p값 | 판정 |
|---|---|---|---|---|
| 50,400 대 49,600 | 50.40% | 6.4 | 0.011 | 엄격한 기준에는 통과, 원인 점검 |
| 50,812 대 49,188 | 50.81% | 26.4 | 2.8e-7 | SRM |
| 821,588 대 815,482 | 50.19% | 22.8 | 1.8e-6 | SRM(원문 예: 우연일 확률 50만분의 1 미만)<Ref n={3} /> |

- 임계값은 0.05가 아니라 훨씬 엄격하게 둔다. 오경보를 줄이려는 관행이다. Microsoft는 p값 0.0005 미만을 쓴다.<Ref n={4} /> 다른 값의 근거는 확인 필요.
- 전체뿐 아니라 날짜별, 기기별 배정 수도 봐서 편차가 생긴 구간을 좁힌다.<Ref n={3} />

원인 후보는 배정 서비스 버그와 실험 간 해시 시드 상관, 변형별 시작 시각 차이와 리다이렉트 실패, 봇 필터가 한 군의 열성 사용자를 제거, 한 군에 치우친 로그 유실이다.<Ref n={3} /> SRM이 있으면 보정해서 분석하지 말고 원인을 고쳐 다시 돌린다.

## 결과를 분석할 때

규칙: 분모는 배정된 사용자 전원, 분자는 배정 후 행동이다. 사용자 1명을 한 번만 센다.

가상 테이블은 `assignments`(사용자, 군, 배정일)와 `orders`(주문, 사용자, 주문일)이고, 15% 사용자는 배정 전 주문이 있다. 먼저 나쁜 쿼리다.

```sql
SELECT a.variant,
  COUNT(DISTINCT a.user_id) AS users,
  COUNT(o.order_id) AS orders,
  ROUND(COUNT(o.order_id) * 100.0
    / COUNT(DISTINCT a.user_id), 2)
    AS cvr_pct
FROM assignments a
LEFT JOIN orders o
  ON o.user_id = a.user_id
GROUP BY a.variant;
```

| variant | users | orders | cvr_pct |
|---|---|---|---|
| A | 15063 | 4123 | 27.37 |
| B | 14937 | 4305 | 28.82 |

증상은 전환율이 비상식적으로 높은 것이다. 원인은 둘이다. 주문 행 수를 전환으로 셌고(한 사용자가 여러 번 센다), 배정 전 주문도 들어갔다. 고친 쿼리는 사용자를 한 번만 세고 배정일 이후 주문만 붙인다.

```sql
WITH g AS (
  SELECT a.variant,
    COUNT(DISTINCT a.user_id) AS users,
    COUNT(DISTINCT o.user_id) AS buyers
  FROM assignments a
  LEFT JOIN orders o
    ON o.user_id = a.user_id
   AND o.ordered_on >= a.assigned_on
  GROUP BY a.variant
), r AS (
  SELECT variant, users, buyers,
    1.0 * buyers / users AS p
  FROM g
)
SELECT variant, users, buyers,
  ROUND(100 * p, 2) AS cvr_pct,
  ROUND(100 * (p - FIRST_VALUE(p)
    OVER (ORDER BY variant)), 2)
    AS diff_pp
FROM r;
```

| variant | users | buyers | cvr_pct | diff_pp |
|---|---|---|---|---|
| A | 15063 | 1483 | 9.85 | 0.00 |
| B | 14937 | 1607 | 10.76 | 0.91 |

시간 조건을 `WHERE`가 아니라 `ON`에 둔 것이 핵심이다. `WHERE`에 두면 주문 없는 사용자가 사라져 분모가 구매자만 남는다(d05). `1.0 *`은 정수 나눗셈을 막는다.

| 방언 | `5 / 2` | 비고 |
|---|---|---|
| PostgreSQL | 2 | 정수끼리는 0 방향으로 버린다<Ref n={5} /> |
| MySQL | 2.5000 | `/`는 소수로 나오고 정수 나눗셈은 `DIV`<Ref n={6} /> |
| BigQuery | 확인 필요 | |

두 비율 z 검정(검정 통계량은 합동 비율, 구간은 각 군 비율의 표준오차)으로 계산하면 차이는 +0.91%p, 95% 신뢰구간 +0.23%p에서 +1.60%p, p=0.0093이다. 보고할 때는 p값만 쓰지 말고 차이와 구간을 같이 쓴다.

## 비율 지표를 분석할 때

규칙: 분자와 분모의 단위가 무작위 단위(사용자)와 다르면(세션당 클릭률, 주문당 금액) 행 단위 검정을 쓰지 마라. 사용자 안의 행은 서로 독립이 아니다.

가상 A/A 모의(사용자 1,000명씩, 사용자마다 클릭 성향이 다르고 세션 수는 평균 약 3.5)를 3,000번 돌린 결과다. 실제 차이가 없는데 유의하다고 나온 비율이다.

| 분석 방법 | 거짓 양성 | 판정 |
|---|---|---|
| 세션을 독립 표본으로 보고 비율 검정 | 14.7% | 목표 5%를 크게 넘는다 |
| 사용자 단위 델타 방법 | 4.7% | 목표 안 |

델타 방법은 사용자 단위로 분자 합과 분모 합을 같이 보고 비율의 분산을 구하는 근사다.<Ref n={7} /> 사용자별 분자를 x, 분모를 y, 사용자 수를 n이라 하면 비율 `mean(x)/mean(y)`의 분산은 아래와 같다.

```text
Var(X/Y) ≈ ( var(x) / mean(y)²
 - 2·mean(x)·cov(x,y) / mean(y)³
 + mean(x)²·var(y) / mean(y)⁴ ) / n
```

- 가장 쉬운 처방은 지표를 사용자 단위로 바꾸는 것이다(사용자당 클릭 수, 클릭한 사용자 비율).
- 비율 지표가 필요하면 델타 방법이나 사용자 단위 부트스트랩으로 구간을 만든다.

## 분산을 줄이고 싶을 때

규칙: 실험 전 같은 지표값이 있으면 CUPED로 분산을 줄여 표본이나 기간을 줄인다.

아이디어는 사용자의 실험 전 값 X로 실험 중 값 Y에서 예측 가능한 부분을 빼는 것이다. `Y' = Y - θ(X - mean(X))`, `θ = cov(X,Y) / var(X)`이다. 평균은 그대로이고 분산이 `(1 - ρ²)`배가 된다. ρ는 X와 Y의 상관계수다.<Ref n={10} /> Bing에서 분산을 약 50% 줄였다는 보고가 있다.<Ref n={10} />

모의(사용자 5만 명, 상관 0.70 가정)에서 분산 비율은 0.506으로 `1 - ρ²`와 같았다. 앞의 평균 비교 예(6,280명)에 적용하면 다음과 같다.

| 상관 ρ(가정) | 분산 배율 | 필요 군당 표본 |
|---|---|---|
| 0.3 | 0.91 | 5,715 |
| 0.5 | 0.75 | 4,710 |
| 0.7 | 0.51 | 3,203 |

- X는 실험 전에 측정한 값만 쓴다. 처치의 영향을 받은 값을 쓰면 효과가 사라진다.
- 실험 전 데이터가 없는 신규 사용자는 보정할 수 없다. 0과 1 지표는 상관이 낮아 효과가 작을 수 있다(일반론).

## 지표와 세그먼트를 여러 개 볼 때

규칙: 판정은 주지표 1개만 5%로 한다. 나머지는 설명용이고, 보면 볼수록 우연히 유의한 것이 나온다.

| 검정 수 m | 하나라도 거짓 양성(α=0.05, 독립 가정) | 본페로니 기준 α/m |
|---|---|---|
| 1 | 5.0% | 5% |
| 10 | 40.1% | 0.5% |
| 20 | 64.2% | 0.25% |

- 가드레일과 보조 지표가 여러 개이면 본페로니나 거짓 발견율(FDR) 보정을 쓴다. 후자는 Benjamini-Hochberg 방식이 대표적이다.<Ref n={11} />
- 세그먼트는 사전에 목록을 정한다. 사후에 찾은 "특정 세그먼트만 유의"는 가설로만 두고 재실험으로 확인한다.

## 사용자끼리 영향을 줄 때

규칙: 한 사용자의 군이 다른 사용자의 결과에 영향을 주면 사용자 단위 비교가 틀어진다. 설계 단계에서 먼저 의심한다.<Ref n={12} />

| 상황 | 영향 방식 | 증상(방향은 설계마다 다름) |
|---|---|---|
| 소셜·메시징(친구 연결) | 처치 사용자가 대조군 친구에게 영향 | 효과가 축소되어 보이기 쉽다 |
| 마켓플레이스·예약(공유 재고) | 처치군이 재고를 더 가져가 대조군이 줄어든다 | 효과가 과대 측정되기 쉽다 |

- 처방: 무작위 단위를 묶음(지역, 연결 그래프의 군집)으로 올리거나, 시간대를 번갈아 처치하거나, 자원을 군별로 분리한다. 방법별 설계 세부는 확인 필요다.<Ref n={12} />

## 결과를 판정할 때

규칙: 판정은 주지표와 가드레일 두 축으로 정한다. 사전에 정한 표를 그대로 쓰고 결과를 본 뒤 기준을 바꾸지 않는다.

<Figure caption="출시는 주지표가 유의하게 좋아지고 가드레일이 악화되지 않을 때뿐이다.">
  <VerdictMatrix />
</Figure>

| 주지표 | 가드레일 | 판정 | 다음 행동 |
|---|---|---|---|
| 유의한 개선 | 악화 없음 | 출시 | 효과 크기는 신뢰구간 하한으로 보고 |
| 유의한 개선 | 악화 | 보류 | 악화 폭과 이득을 비교, 보완 후 재실험 |
| 유의하지 않음 | 악화 없음 | 재실험 또는 종료 | 구간 상한이 MDE보다 작으면 종료, 아니면 표본 확대 |
| 유의하지 않음 | 악화 | 출시 안 함 | 악화 원인을 조사 |
| 유의한 악화 | 무관 | 폐기 | 가설을 다시 세운다 |

"유의하지 않음"은 "효과 없음"이 아니다. 신뢰구간이 MDE 이상의 효과를 배제하지 못하면 표본이 모자란 것이다.

## 흔한 실수

| 나쁜 예 | 고친 예 | 이유 |
|---|---|---|
| 유의해 보이는 날 멈춘다 | 계획 표본에서 한 번만 판정 | 확인할수록 거짓 양성이 오른다 |
| 3일 만에 끝낸다 | 7일의 배수로 돌린다 | 요일 효과가 쏠린다 |
| SRM을 보지 않고 결과만 본다 | 결과 전에 군별 수 확인 | 편향된 군을 비교하게 된다 |
| 세션 단위 비율을 행 단위로 검정 | 사용자 단위나 델타 방법 | 거짓 양성이 14.7%까지 오른다 |
| 지표 20개를 훑어 유의한 것을 보고 | 주지표 1개로 판정, 나머지는 보정 | 하나는 우연히 나온다 |

## 증상으로 찾기

| 증상 | 원인 | 처방 |
|---|---|---|
| 군별 사용자 수가 설계와 다르다 | 배정, 실행, 로그 처리 중 하나의 편향 | p값을 확인하고 날짜·기기별 배정 수로 시점을 좁힌다 |
| 처음엔 크게 유의하다가 줄어든다 | 신규 효과 또는 중간 확인 | 경과일별 효과를 보고 연장한다 |
| 전환율이 비상식적으로 높다 | 주문 행 수를 센 것, 배정 전 이벤트 포함 | 사용자 수준 중복 제거와 배정 후 조건 |
| 재실험하면 결과가 자주 뒤집힌다 | 행 단위 검정으로 구간이 실제보다 좁다(비율 지표) | 사용자 단위 분석이나 델타 방법 |
| 출시 후 효과가 실험보다 작다 | 간섭, 신규 효과 | 묶음 단위 배정, 장기 관찰 |

## 점검 체크리스트

- 가설, 무작위 단위, 주지표 1개, 가드레일, 기간이 시작 전에 문서로 있는가.
- 표본 수를 MDE, 검정력 80%, 양측 5%로 계산했고 가정을 적었는가.
- 기간이 7일의 배수이고 신규 효과를 확인할 경과일별 지표가 있는가.
- 결과를 열기 전에 SRM(카이제곱, 날짜·기기별)을 확인했는가.
- 분모가 배정된 사용자 전원이고 분자가 배정 후 행동인가.
- 비율 지표의 분석 단위가 무작위 단위와 같거나 델타 방법을 썼는가.
- 중간 확인이 계획에 있으면 보정했는가. 없으면 종료일까지 판정하지 않았는가.
- 사용자 간 영향(공유 자원, 네트워크)을 검토했는가.

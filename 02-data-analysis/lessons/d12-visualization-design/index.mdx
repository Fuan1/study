## 질문에 맞는 차트를 고를 때

규칙: 데이터 모양이 아니라 질문으로 고른다. 질문을 한 문장으로 쓰고 그 문장이 비교인지, 추이인지, 구성인지부터 가려라.

| 질문 | 권장 차트 | 피할 차트 | 이유 |
|---|---|---|---|
| 비교: 누가 더 큰가 | 막대, 점 차트 | 파이, 레이더, 3D 막대 | 길이와 위치로 읽히는 쪽이 정확하다 |
| 추이: 시간에 따라 어떻게 변하나 | 선 차트. 시점이 몇 개뿐이면 세로 막대 | 시점마다 파이 하나씩 | 점이 이어져야 방향과 기울기가 보인다 |
| 구성: 전체 중 얼마씩인가 | 100% 누적 막대. 한 시점에 5조각 이하면 파이 | 6조각 이상 파이, 도넛 여러 개 | 조각이 많으면 크기를 비교할 수 없다 |
| 분포: 값이 어떻게 퍼졌나 | 히스토그램, 박스플롯 | 평균만 그린 막대 | 평균은 퍼짐과 치우침을 숨긴다 |
| 관계: 두 수치가 함께 움직이나 | 산점도 | 이중 축 선 차트 | 축 눈금을 어떻게 맞추느냐에 따라 관계가 달라 보인다 |
| 순위: 몇 번째인가 | 값 순 정렬 가로 막대, 점 차트 | 정렬하지 않은 막대, 파이 | 순서가 곧 정보다 |

## 축을 정할 때

규칙: 축 규칙은 차트 종류마다 다르다. 막대는 0에서 시작하고, 선은 조건이 맞으면 0이 아니어도 된다.

| 규칙 | 기준 | 조건과 예외 |
|---|---|---|
| 막대 기준선 | 0에서 시작한다. 길이가 값을 뜻하므로 축을 자르면 차이가 부풀어 보인다<Ref n={3} /> | 차이가 작아 안 보이면 값 대신 증감을 그린다 |
| 선 차트 기준선 | 0이 아니어도 된다. 선은 면적이 아니라 점의 위치로 읽힌다<Ref n={4} /> | 값이 0 근처이거나 비율이면 0이나 100을 포함한다. 축 범위를 적는다 |
| 이중 축 | 쓰지 않는다. 눈금을 어떻게 맞추느냐에 따라 두 선의 관계가 달라 보인다<Ref n={5} /> | 차트 둘을 나란히 놓거나, 기준 시점을 100으로 맞춘 지수 차트를 쓴다 |
| 로그 축 | 값이 몇 자릿수에 걸치고 증가율이 관심일 때만 쓴다. 1과 10의 간격이 10과 100의 간격과 같다<Ref n={6} /> | 축에 로그 눈금이라고 적는다. 0과 음수는 못 그리므로 막대에 쓰지 않는다 |
| 같은 비교는 같은 축 | 나란히 놓는 차트(기간별, 지역별)는 축 범위를 같게 한다 | 다르게 해야 하면 모든 패널에 눈금을 보이게 한다<Ref n={7} /> |

## 값을 어떤 모양으로 보일지 정할 때

규칙: 정확히 비교해야 하는 값은 위치와 길이로 보인다. 면적·각도·색 농도는 대략을 보일 때만 쓴다.

값을 읽는 정확도는 공통 눈금 위의 위치, 길이·각도, 면적, 색 농도 순으로 떨어진다는 것이 지각 연구의 정리다.<Ref n={8} /> 크라우드소싱으로 재현한 실험도 같은 방향이었다.<Ref n={9} />

| 인코딩 | 쓸 때 | 하지 마라 |
|---|---|---|
| 위치(점, 선) | 정확한 비교, 추이 | 눈금과 단위 없이 그리기 |
| 길이(막대) | 크기 비교, 순위 | 0이 아닌 기준선 |
| 각도·면적(파이, 버블, 트리맵) | 구성의 대략, 몫이 눈에 띄게 큰 값 | 차이가 작은 조각을 비교시키기 |
| 색 농도(히트맵) | 패턴 찾기 | 정확한 값을 색으로 읽게 하기 |

파이는 조각 수와 용도로 판단한다.<Ref n={10} />

| 기준 | 값 | 넘으면 |
|---|---|---|
| 조각 수 | 5개 이하 | 100% 누적 막대로 바꾸고 작은 조각은 기타로 묶는다 |
| 합계 | 100%인 한 시점 | 여러 시점은 누적 막대로 비교한다 |
| 용도 | 몫이 25%, 50%, 75% 근처로 눈에 띌 때 | 순위·비교가 목적이면 막대 |
| 라벨 | 조각 옆에 이름과 값을 직접 쓴다 | 범례를 쓰지 않는다 |

<Figure caption="같은 다섯 값(가정)이다. 22와 21 같은 가까운 값의 순서는 파이에서 읽히지 않고, 정렬한 막대에서는 길이로 읽힌다.">

이 순위는 값을 숫자로 읽는 정확도 연구에서 나온 것이다. 파이를 쓰면 안 된다는 뜻이 아니라, 값 차이를 읽어야 하는 질문에 파이를 쓰지 말라는 뜻이다.
</Callout>

## 색을 쓸 때

규칙: 색은 구분과 강조에만 쓴다. 강조할 것 하나만 색을 주고 나머지는 회색으로 둔다.

| 색 종류 | 쓸 때 | 규칙 |
|---|---|---|
| 범주형 | 순서 없는 그룹 | 색상을 달리한다. 한 차트 7색 이하가 관행이고, 넘으면 묶거나 다른 차트로 바꾼다<Ref n={11} /> |
| 순서형 | 작음에서 큼 | 한 색상의 밝기 차로 쓴다. 밝기 범위가 넓어야 작은 차이가 보인다<Ref n={12} /> |
| 발산형 | 기준값(0, 평균)에서 위아래로 갈릴 때 | 두 색상이 중립색에서 만나게 하고 중립을 기준값에 맞춘다<Ref n={11} /> |
| 강조 | 이야기할 값 하나 | 그 하나만 색을 주고 나머지는 회색으로 둔다<Ref n={11} /> |

### 색약을 고려할 때

색각 이상은 남성 약 12명 중 1명이다.<Ref n={13} /> 여성은 0.5% 안팎으로 알려져 있다.<Ref n={2} /> 구분 색으로 빨강과 초록 쌍을 쓰지 마라. 파랑과 주황 쌍으로 바꾼다. 팔레트는 색각 이상에서도 구분되도록 설계된 Okabe-Ito 8색을 쓸 수 있다.<Ref n={14} />

- 검정 `#000000`, 주황 `#E69F00`, 하늘 `#56B4E9`, 청록 `#009E73`
- 노랑 `#F0E442`, 파랑 `#0072B2`, 주홍 `#D55E00`, 자주 `#CC79A7`

### 대비와 색만으로 구분하지 않기

그래픽 요소는 인접한 색과 3:1 이상 대비해야 한다(WCAG 1.4.11).<Ref n={15} /> 위 팔레트를 WCAG 상대 휘도 공식으로 계산하면 흰 배경에서 검정 21.0, 파랑 5.2, 주홍 3.9, 청록 3.4, 자주 3.1은 통과하고, 하늘 2.3, 주황 2.3, 노랑 1.3은 미달이다. 어두운 배경(#141415)에서는 검정만 1.1로 미달이다. 색약용 팔레트라고 대비까지 보장하지 않으므로 배경에 맞춰 따로 확인한다.

- 색만으로 구분하지 마라. 직접 라벨, 선 모양(실선·점선), 마커, 위치를 함께 쓴다.
- 좋음·나쁨 같은 의미 색은 한 차트에서 한 가지 의미로만 쓰고, ▲▼ 기호를 같이 붙인다.

## 제목과 주석을 달 때

규칙: 제목은 결론, 부제는 단위와 기간, 라벨은 직접, 출처는 아래에 쓴다.

| 요소 | 규칙 | 나쁜 예 → 고친 예 |
|---|---|---|
| 제목 | 결론을 일상어 한 문장으로 쓴다<Ref n={16} /> | 월별 매출 → 6월 서울 매출이 1월보다 28% 높다 |
| 부제 | 지표, 단위, 기간, 기준을 쓴다 | 없음 → 월 매출 지수(1월=100), 2025년 1월부터 6월 |
| 라벨 | 범례 대신 선 끝과 막대 옆에 직접 쓴다 | 범례 4개 → 선 끝에 이름과 값 |
| 주석 | 이야기에 필요한 지점에만 단다 | 점마다 설명 → 급등한 달에만 한 줄 |
| 출처·기준일 | 아래에 작은 회색 글씨로 쓴다 | 없음 → 자료: 가정 데이터, 기준일 7월 1일 |

- 항목이 많아 직접 라벨이 겹치면 범례를 쓴다. 모바일에서 공간이 모자라도 범례를 차트 위에 둔다.

## 정렬하고 정리할 때

규칙: 값 순으로 정렬하고, 값 읽기에 필요하지 않은 장식은 지운다.

| 규칙 | 기준 | 예외 |
|---|---|---|
| 막대 정렬 | 큰 값부터 정렬한다. 순위 차트는 순서가 곧 정보다<Ref n={1} /> | 시간, 나이대, 단계처럼 자연 순서가 있는 범주는 그 순서 |
| 장식 제거 | 3D, 그림자, 배경 무늬를 지운다. 3D 는 값 비교를 왜곡한다<Ref n={2} /> | 격자는 눈금 읽기에 필요한 만큼만 옅게 |
| 소수점 | 같은 차트와 같은 열은 자릿수를 통일한다 | 의미 있는 차이가 보이는 최소 자릿수 |
| 큰 수 | 12.8k 처럼 줄여 쓸 수 있다<Ref n={16} /> | 정확한 값이 필요하면 표 |

소수점 통일은 12.5%, 8%, 10.25% 를 12.5%, 8.0%, 10.3% 로 고치는 것이다. 자릿수가 섞이면 큰 값이 더 정확해 보인다.

## 대시보드를 만들 때

규칙: 한 화면은 질문 하나에 답한다. 핵심 지표를 맨 위에 두고, 필터는 기본값이 보이게 둔다.

| 항목 | 기준 | 비고 |
|---|---|---|
| 화면당 질문 | 하나. 한눈에 보고 바로 행동할 수 있게 한다<Ref n={2} /> | 질문이 둘이면 화면도 둘 |
| 배치 | 핵심 지표, 추이, 세부 순서로 위에서 아래 | 가장 중요한 것이 맨 위 |
| 개수 | 한 화면에 핵심 지표 2에서 3개, 차트 1에서 2개 | 우리 권장 관행이며 공식 수치가 아니다 |
| 필터 기본값 | 가장 많이 쓰는 보기(예: 최근 28일, 전체)로 두고 화면에 보이게 한다 | 사용 기록으로 정한다. 바꾸면 제목의 기간도 바뀌게 한다 |
| 글자 크기 | 12px 미만은 작을 가능성이 크다<Ref n={17} /> | 폰 폭에서 직접 확인한다 |
| 터치 영역 | 필터 칩은 24×24 CSS px 이상<Ref n={15} /> | 간격이 충분하면 예외(WCAG 2.5.8) |

| 이중 축 선 차트 | 차트 둘 나란히 또는 지수 차트 | 눈금을 맞추는 방식으로 관계가 만들어진다 |

| 빨강과 초록으로 좋음·나쁨 | 파랑과 주황, ▲▼ 병기 | 색각 이상에서도 구분된다 |
| 제목 "월별 매출" | 결론 제목과 단위·기간 부제 | 읽자마자 결론이 나온다 |
| 정렬하지 않은 막대 | 값 순 정렬 | 순위가 한눈에 보인다 |
| 3D 막대와 그림자 | 2D 평면 막대 | 높이 비교가 정확하다 |
| 한 화면 차트 8개 | 질문 하나, 차트 1에서 2개 | 모바일에서 읽힌다 |

## 증상으로 찾기

| 증상 | 원인 | 처방 |
|---|---|---|
| 그림은 차이가 큰데 숫자는 비슷하다 | 막대 축이 0이 아니다 | 0에서 시작하고 증감을 따로 그린다 |
| 두 선이 같이 움직이는 것 같은데 설명이 안 된다 | 이중 축 눈금 맞춤 | 차트를 나누거나 지수로 맞춘다 |
| 독자가 범례와 차트를 오간다 | 색이 많고 범례를 쓴다 | 직접 라벨, 강조 1색과 회색 |
| 색약 동료가 계열을 못 구분한다 | 빨강·초록 쌍, 색만으로 구분 | Okabe-Ito 같은 팔레트, 라벨·선 모양 병행 |
| 회의에서 "그래서 결론이 뭐냐"고 묻는다 | 설명형 제목 | 결론 제목으로 바꾼다 |
| 폰에서 글자가 작고 차트가 잘린다 | 데스크톱 기준 대시보드 | 차트를 줄이고 글자 12px 이상, 세로로 쌓는다 |
| 필터를 바꾸니 제목과 숫자가 안 맞는다 | 제목의 기간이 고정 | 제목과 부제를 필터에 연동한다 |

## 점검 체크리스트

- 질문 한 문장에 맞는 차트인가(비교, 추이, 구성, 분포, 관계, 순위).
- 막대 차트의 축이 0에서 시작하는가.
- 이중 축을 쓰지 않았는가. 로그 축이면 축에 적었는가.
- 나란히 놓은 차트의 축 범위가 같은가.
- 파이는 5조각 이하이고 합이 100%인가.
- 구분 색이 7가지 이하이고 강조는 한 색인가.
- 색만으로 구분한 곳이 없는가. 그래픽 요소 대비가 3:1 이상인가.
- 제목이 결론이고 부제에 단위와 기간이 있는가.
- 출처와 기준일이 아래에 있는가.
- 막대가 값 순이고 소수점 자릿수가 같은가.
- 대시보드 한 화면이 질문 하나이고 핵심 지표가 맨 위인가.
- 폰 폭(약 390px)에서 글자가 12px 이상으로 읽히는가.
